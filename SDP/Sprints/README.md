# Sprints

A Sprint is an optional group of selected KanBan cards under one goal. Use one
concise Sprint record with SPR-SDP-NNNN identity, source Scrum, member card IDs,
status, intended acceptance and final disposition. Cards stay in KanBan lifecycle
directories and carry SprintId; do not copy them into this area. Current membership
must agree with the record and changes append management events.

Use the [project-management contract](../ProjectManagement/README.md) for start,
completion, cancellation and history. Selected backlog cards move to active/ready
when the Sprint starts. Independent cards and Scrum → Maintenance are valid.
Do not invent a Sprint for completed work solely to fill a hierarchy.

Existing Sprint directories retain dated scope and identifiers. Their richer
iteration/notes/handoff documents remain historical authorities; new work need
not create empty equivalents. Actual system design/code changes are recorded in
Traceability with references to the Sprint's management identity/event.
