## Outcome and selected design

Default CLI output is readable without json-tree.sh. Explicit --json preserves
machine result schemas. A Go presentation package receives the serialized result
and routes by schema plus operation to compiled-in renderers. An unknown route
falls back to the original JSON. Typed core APIs, generated artifacts, command
semantics and exit status retain their existing responsibilities. Presentation is
an in-process unit of SdpToolProcess, not another deployed container. There is no
shell/jq runtime dependency, dynamic plugin loading, GUI or new language feature.

Tree output follows root/child order, displays labels and states, and terminates
on reference/cycle/depth limits. Other known results use a deterministic readable
field hierarchy; version and errors get concise renderers. Installation retains
its existing human summary and JSON stdout/error contract through a registered
adapter. Release-log keeps Markdown export in human mode; --json wraps the same
content or generation receipt. Help remains usage text.

## Compatibility and consumers

Changing JSON-by-default is an intentional public CLI break. Machine consumers
must opt in with --json, including packaging and bootstrap version probes. The
bootstrap first requests explicit JSON and retries legacy --version only if the
read-only probe fails, retaining protocol verification. No mutating retry.
Published old gh-sdp clients need a bootstrap update before selecting this engine;
XFMD callers need explicit --json. Native XFMD code and gh-sdp publication are
outside this workstream. Document that handoff before claiming release readiness.
Under the current version contract the next combined candidate is **2.0.0**, which
supersedes RL1's additive 1.1.0 proposal, not the historical preparation evidence.
Published SDP remains 1.0.0; no manifest/tag/publication change is performed here.
