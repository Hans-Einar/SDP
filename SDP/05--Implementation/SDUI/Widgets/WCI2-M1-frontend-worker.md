## Delivery and API boundary

The .3 grammar/parser accepts bracketed call bodies; local validation requires and
permits them only for tabs/page/split. Existing fields represent them as composition
nodes with Widget/Arguments/Rows. Body assignments are names, not frame regions.
Schema checks cover required/nonblank labels, optional symbolic icons, named tabs
callbacks, direct selected-page identity/eligibility, typed finite split values and
exact child cardinality. Placement is checked after reuse expansion; reusable page
roots are allowed, embedding a page outside tabs is not. Split defaults normalize
as typed Literals (.5/0/0/true); absent tabs selection stays absent for runtime.

New additive public parser API: PaneChild{ID string; Node *Instance} and
PaneChildren(*Instance) ([]PaneChild,error), returning ordered direct named IDs.
It validates tabs/split cardinality, direct paths, child profile and page kind.
No Instance/Node fields, AST tags, generator versions or command path schemas added.
Callback references remain Arguments entries; existing setHandle targets remain
ordinary widgets. New composition consumers must check Kind and capabilities;
EffectiveProfile alone is not support admission.

The frontend API/inventory memo was sent directly to runtime James, layout Gibbs,
host Noether, bridge Lorentz and main before dependent implementation. Main accepted
the routine boundary. Runtime confirmed local page eligibility intent is separate
from inactive tabs ancestry, consistent with frontend initial-selection validation.

Codegen's existing typed literal machinery handles the new composition rows and
normalized defaults without product generator changes. A new compiled-constructor
round-trip test proves source/profile/binding/reuse identity and mutable isolation.
The profile remains unreleased sdui/0.3, AST sdui-ast/0.3, generator sdui-go-model/2.
Frozen default 0.2 source/AST/generated bytes remain unchanged.

Text/Markdown/composition display pane identities, labels, initial selection,
split constraints, symbolic callbacks/icons and visibility intent as static facts.
All pane declarations, including hidden ones, appear in the description; existing
visibility policy still governs body text. Pane descriptions share the bounded cell
budget. Unknown future node kinds reject even in hidden content. No native geometry,
provider data or live selected state is invented.

Public SVG rejects panes with unsupported-pane-export, source path/span, even hidden
or when measured geometry is supplied. Native SkipControls requires exact tabs/split
path-to-kind entries plus all descendant button/input/tree/list controls, including
inactive pages. Page has no inventory entry: its header/shell belongs to prepared
tabs. Native chrome omission does not bypass descendant validation or background
content rendering. Extra/wrong/missing entries and unknown future kinds reject.
No existing Options field or public signature changed; WCI1 leaf inventory semantics
and ordinary 0.2 export remain unchanged.

Standalone prototype preflight reports unsupported-pane with typed host capability,
path and span, including hidden panes; it never claims native/connected readiness.
