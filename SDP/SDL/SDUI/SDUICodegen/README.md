Produce Go constructors for the validated SDUI document and selected instance model so an application can start without reading UI source files.

## Ownership and implementation

`SDUI/go/codegen.Generate(source, entry, pkg)` is the implemented library entry. The combined `SDL/go/cmd/sdl-gen` binary orchestrates SDUI and SDL generation and writes an owned-file manifest. A distinct SDUI compiler CLI, release and installed binary are proposed, not delivered.

The system owns the modeled core and its internal units. `GenerationCaller` is a
context participant, not an additional deployed product. `SdlGenerationCommand` represents
the actual embedding process role; it is not a new binary created by this model.
Shared package boundaries and extraction targets are separate from current process
deployment. [Ecosystem coverage](../README.md) records the combined entrypoints.

## Public boundary and scenarios

The input package is validated before generation; source is compiled by SDUIFrontend. Output includes `Document()`, `Root()` and `UISourceSHA256`. Generation targets the existing parser model types and Go formatting. `Generate` returns bytes/error and does not build an executable or publish files.

`GenerateUiGoAccepted` and `GenerateUiGoRejectedScenario` describe the successful and
rejected logical call paths. The success result projection includes diagnostics; the rejection message has a
separate diagnostic-only contract and no generated/model/presentation payload. These named messages/channels
are analysis projections of Go calls, not shipped RPC names or wire contracts.
The closed contracts close only this deliberately bounded projection. They do
not claim all implementation fields or every interaction have been modeled.
Modes name operational contexts and do not implement a state machine.

## Limits and unresolved packaging

This compiles declarative models to constructors, not an arbitrary SDUI interpreter or domain program. Handwritten Go behavior, manifests, build/restart and SDL action generation remain outside this library. A stable cross-release generated-model ABI has not been selected.

Dedicated binary naming, installation and independently versioned library releases
remain extraction decisions. SDPTool can orchestrate public CLI or Go library
entrypoints; this model does not add a dependency or claim all integrations exist.

## Validate and browse

From the repository root:

```sh
go -C SDL/go run ./cmd/sdl check ../../SDP/SDL/SDUI/SDUICodegen/System.design
go -C SDL/go run ./cmd/sdl ast ../../SDP/SDL/SDUI/SDUICodegen/System.design
go -C SDL/go run ./cmd/sdl viewpoints ../../SDP/SDL/SDUI/SDUICodegen/System.design --format static --output /tmp/sdp-sdui-sduicodegen
```

The single entry is independent; no import, source-set registration or implicit
folder namespace is assumed. Output is generated by SDL tools, never authored by
hand. Parser success validates this model, not native/runtime behavior. Model
navigation registration in SDPTool remains explicit; merely adding this folder
does not install a navigation project.
