Measure normalized UI instances, compute reusable geometry and render static SVG or structural console/Markdown exports without invoking domain behavior.

## Ownership and implementation

`layout`, `markdown`, `svg` and `presentation` are packages in `SDUI/go`. The existing `sdui --format svg|dump|markdown` CLI combines these with the frontend. Fyne consumes shared layout geometry but owns native controls. No extracted presentation binary or network renderer is present.

The system owns the modeled core and its internal units. `ExportCaller` is a
context participant, not an additional deployed product. `SduiExportCommand` represents
the actual embedding process role; it is not a new binary created by this model.
Shared package boundaries and extraction targets are separate from current process
deployment. [Ecosystem coverage](../README.md) records the combined entrypoints.

## Public boundary and scenarios

The modeled SVG call is a logical summary of `markdown.Prepare`, `layout.Engine.Layout` and `svg.Render`. Actual viewport dimensions are Go float64 logical units, represented here by decimal fields. `InstanceProjection` represents an already normalized in-memory tree; its serialization is not defined here.

`RenderUiAccepted` and `RenderUiRejectedScenario` describe the successful and
rejected logical call paths. The success result projection includes diagnostics; the rejection message has a
separate diagnostic-only contract and no generated/model/presentation payload. These named messages/channels
are analysis projections of Go calls, not shipped RPC names or wire contracts.
The closed contracts close only this deliberately bounded projection. They do
not claim all implementation fields or every interaction have been modeled.
Modes name operational contexts and do not implement a state machine.

## Limits and unresolved packaging

Text is bounded Markdown, not full browser Markdown/HTML. Embedded Mermaid needs an explicitly configured renderer; tested support is flowchart/graph, not every diagram family. SVG widgets remain placeholders. Structural Markdown dump is not an interactive form. Relative source dimensions do not forbid host viewport measurements in logical units.

Dedicated binary naming, installation and independently versioned library releases
remain extraction decisions. SDPTool can orchestrate public CLI or Go library
entrypoints; this model does not add a dependency or claim all integrations exist.

## Validate and browse

From the repository root:

```sh
go -C SDL/go run ./cmd/sdl check ../../SDP/SDL/SDUI/SDUIPresentation/System.design
go -C SDL/go run ./cmd/sdl ast ../../SDP/SDL/SDUI/SDUIPresentation/System.design
go -C SDL/go run ./cmd/sdl viewpoints ../../SDP/SDL/SDUI/SDUIPresentation/System.design --format static --output /tmp/sdp-sdui-sduipresentation
```

The single entry is independent; no import, source-set registration or implicit
folder namespace is assumed. Output is generated by SDL tools, never authored by
hand. Parser success validates this model, not native/runtime behavior. Model
navigation registration in SDPTool remains explicit; merely adding this folder
does not install a navigation project.
