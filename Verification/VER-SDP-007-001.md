## Findings

### F01 — High — concurrency graph and convergence safety are not enforced

`ConcurrentAssignments.md` states that `dependsOnIssues` is a directed acyclic
prerequisite edge and that concurrent work requires an ordered merge contract
plus a convergence branch/gate. `validate_assignments` compares whether peers
copy the same merge/convergence values, but it does not validate dependency
acyclicity or non-empty/useful merge and convergence contents.

Independent mutations created a two-Issue dependency cycle and, separately,
empty `mergeOrder`/`convergence` values in both assignments. Both returned an
empty diagnostic list. An invalid concurrent set can therefore receive the
validator's PASS despite lacking a legal convergence order.

Required rework: validate unique Issue graph nodes, dependency references and
acyclicity; require a non-empty merge order covering the active assignments;
require a non-empty convergence owner/command or another explicitly supported
gate shape; add exact negative fixtures and coverage assertions.

### F02 — Medium — one-Issue/one-primary-work cardinality is not enforced

`WorkflowContract.md` defines one Issue as one bounded assignment and gives
Issue-to-primary-work cardinality exactly `1`. The validator builds an
`issue_map` dictionary, which silently overwrites duplicate Issue URLs.

After removing unrelated shared-touchpoint noise, two assignments with the
same Issue URL and different primary work returned no diagnostic. That permits
ambiguous assignment recovery and breaks the durable Issue boundary.

Required rework: reject duplicate assignment authority URLs (or define and
validate an explicit revision/supersession representation that leaves only one
current assignment contract); add a negative fixture.

### F03 — Medium — active domain-root parent overlap is accepted

`WorkDomains.md` says active roots cover domain trees and overlapping active
roots across domains are invalid. The validator passes roots through the same
exact-versus-`/**` reservation overlap function. Because ordinary domain roots
do not end in `/**`, `SDP` and `SDP/HSX` are treated as non-overlapping exact
paths.

Changing the AVR example root to `SDP` while peer active roots remained
`SDP/HSX`, `SDP/Debugger`, and `SDP/Shared` returned no diagnostic. This allows
ambiguous domain ownership and unsafe discovery.

Required rework: treat domain roots as tree roots for root-to-root collision
comparison independently of assignment reservation syntax; add parent/child,
case, slash, and Unicode root fixtures.

### F04 — Medium — forbidden path characters introduced by NFKC are accepted

The path contract requires NFKC/casefold normalization and rejects colon and
glob/platform-unsafe characters. `normalize_path` checks raw characters before
calling `portable_text` on each segment and does not recheck the normalized
segment.

The owned path `research/ＡＶＲ：evidence/**` normalizes to a segment containing
ASCII `:`, but validation returned no diagnostic. Compatibility forms of other
forbidden characters have the same ordering risk.

Required rework: normalize each segment before all forbidden-character,
reserved-name, dot-segment, separator, and glob checks; add NFKC compatibility
fixtures for colon, glob characters, and separators.
