#### M-001 — Required authority, recovery, owner, and cardinality field values are only presence-checked

**Locations:** `SDP-vnext-pilot/validate_pilot.py`, especially lines 236-280,
283-353, 431-489, 599-699, and 915-1053; the required durable meanings are in
`IssueContract.md`, `ConcurrentAssignments.md`, `WorkDomains.md`, and the
assignment/domain templates.

The contract requires one durable GitHub Issue authority, an exact recovery
branch/draft-PR binding, explicit non-empty domain owners, and list-valued
Issue authorities/cardinalities. The validator mainly proves that the keys
exist. Four independent nearby mutations returned no diagnostics:

1. Replaced the Issue URL consistently with `not-a-github-issue-url` in the
   assignment, owner, Slice, issued-ID inventory, reservation row, and merge
   order, then rebound the real digest: `[]`.
2. Replaced `baseline.branch`, `delivery.branch`, and
   `delivery.pullRequest` with empty strings: `[]`.
3. Replaced a domain's `owners` with `[""]`: `[]`.
4. Replaced the Feature's list-valued `issueAuthorities` with the scalar Issue
   URL string. Python string `.count(issue)` happens to return one, so the
   bidirectional cardinality check also returned `[]`.

This is not a request for final canonical schema freeze. These are values the
pilot already marks as required for recovery, scoped ownership, and one-Issue
authority. A first HSX pilot could receive a green validator result while no
resolvable Issue/PR or real shared-domain owner exists, or while the record
shape is not the advertised list shape.

Required rework: validate non-empty strings and collection types for the
required pilot fields; require unique, syntactically valid full GitHub Issue
URLs for authority/Issue lists and a syntactically valid planned PR URL; reject
empty/invalid branch names; require each domain owner to be a non-empty string;
and add exact negative fixtures for these cases. If generic non-GitHub
authorities are intentionally supported later, define a separate explicit
authority-key type rather than accepting arbitrary strings under `issue`.

#### M-002 — The conflict/dependency graph accepts self-conflict and duplicate edges

**Locations:** `SDP-vnext-pilot/ConcurrentAssignments.md`, especially
“Dependencies, conflicts, and merge order”; `validate_pilot.py`, lines 837-901
and 951-960.

The scoped three-Issue example was changed so Issue 203 listed itself in
`conflictsWithIssues` in both the assignment and canonical reservation row;
the real reservation digest was rebound. The validator returned `[]`. The
symmetry test treats the same row as its own reciprocal endpoint. A separate
nearby mutation duplicated Issue 201 in Issue 203's dependency list, rebound
the set, and also returned `[]`.

A self-conflict is not a valid concurrent assignment relationship: it makes
activation/convergence semantics impossible while still receiving the claimed
graph PASS. Duplicate edges are less dangerous, but show that the adjacency
lists are not validated as sets even though the contract models unique graph
edges.

Required rework: reject `issue` in its own `conflictsWithIssues`, require
unique dependency and conflict targets per row, retain the existing local
endpoint/DAG/symmetry/order checks, and add exact negative fixtures. A
self-dependency is already rejected and should remain so.
