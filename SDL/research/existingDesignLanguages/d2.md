# D2

[Catalogue](README.md) · Category: **Diagram DSL** · Research: **2026-09-10**

## Purpose and abstraction level

Declarative text-to-diagram language with objects, connections and visual organization; relevant as an alternative rendering backend.

## Model mechanisms

Identity: object keys/nested objects. Relations: connections. Contracts: labels/metadata, not wire/behavior validation. Views: diagram composition/separate presentations. Extension: imports/tool integration.

## Strengths and limitations — our assessment

**Strength:** Compact diagram text with useful visual control; can show a feature pathway without copying the whole model.

**Limitation:** Shapes/layout do not replace domain semantics. Additional annotations need defined meaning outside drawings.

## History, change and transitions

Diagram scenarios/text versioning do not imply responsibility migration. Git and an external transition model are needed.

## Illustrative example

Diagram text showing relations, not ownership or verified import rules. The example has not been parser/runtime tested.

```d2
domain -> representation: measurement
representation -> composition
composition -> presentation
presentation -> renderer
```

## Tools, maintenance and terms
