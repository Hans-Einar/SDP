# G4 — verification evidence

These are milestone observations, translated without rerunning the original probes.

## G4-M1

Go 1.27.1, structural design-core 0.5 port. `go test -race ./...` passed.
151 frozen cases captured from 61 Python tests compare complete ASTs, argument/end
positions, diagnostic codes/spans and canonical text. The port tool was a temporary
fixture oracle; Go does not invoke Python. The SDUI model (463 declarations,
1424 facts) has an identical full AST to its stored Python export and passes
canonical validation.

A five-second, two-worker fuzz campaign completed 98,637 executions without failure
(about six seconds total). Separate tests cover truncation, UTF-8 and source limits.
Go limits are 2 MiB and 250,000 tokens; structural cycles are checked iteratively.
`sdl ast|check|format file|-` runs. This proves the existing structural profile,
data/wire contracts and Channel/scenario validation, not checkpoint candidates or
the entire MVP1 corpus. Runtime actions follow in M2.

## G4-M2

Explicit `action-core 0.1` has its own grammar/contract and shares the SDL lexer and
positions. Race tests passed; the frozen structural 0.5 port remained identical.
`sdl action-check examples/echo.sdl` passed. Negative cases cover unknown
version/type, incomplete signatures, repeated fields, undeclared records and
incorrect subjects.

Runtime creation requires complete Go registration with matching types. Tests cover
strict input/output checking, copied records, immutable compilation input, missing
or mismatched signatures, stale model revisions, duplicate commands, invalid output
and handler panic without automatic replay. Calls are serialized; a registered
function cannot re-enter the same Engine. Go functions own domain state. This does
not execute design-core facts automatically.

## G4-M3

Race tests passed. Echo sends button/input events through SDUI session → SDL action
→ registered Go function → typed UI update. Invalid module, member, result handle,
field source, literal type and unused plan are rejected before partial installation
or domain calls. Links preserve source positions on both sides.

EditAptCell sends `LengthA1`, draft and expected domain revision. Accepted 430 updates
domain/UI; invalid values or stale revisions retain the accepted value and observable
draft. Duplicate commands are not replayed. `edit-apt-cell-trace.json`, produced by
`go run ./cmd/sdl-simulate` for 430 → invalid → 440, records revision 2 and accepted 440.

The desktop-tagged OpenGL probe `bridge/cmd/smoke` ran under Xvfb. A native button
sent 430 across SDL/Go. A subsequent invalid edit was rejected; Escape restored 430
without another call. Two invocations, one acceptance, one rejection, domain revision
1. `native-binding.png` is a visually checked X11 capture. This is simulation, not
Ponsse/machine runtime. Launch: `go run -tags desktop ./cmd/sdl-demo` here.

## G4-M4

Both modules' race suites passed. Reload waits for the in-flight SDL call's commit
boundary, validates against registered Go signatures and preserves Go-owned state.
Tests cover failed reload without publication, successful replacement, rejected old
events and retained draft/value. Bindings validate before replacement. The shared
watcher is bounded and hash-based, supports rename and never replays actions.

The desktop demo ran under Xvfb. Invalid SDUI retained its UI/diagnostic while valid
SDL published. Atomic recovery showed a new heading, SDUI r3, SDL r2 and unchanged
domain revision 0. Both `dual-reload*.png` X11 captures were checked visually. This
complements automated tests with changed domain state and callbacks.

`sdl-dev` builds/runs an explicit package. An integration test builds a real Go
program, introduces compiler errors and confirms the same process survives;
corrected source starts a new process with new output. Close stops its owned process
group. Go restart does not preserve memory automatically: this is build/restart,
not dynamic machine-code replacement. Linux was verified.
