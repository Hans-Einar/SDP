# G5 — Go generation and consolidated documentation

Historical milestone evidence; translation does not constitute a new test run.

## G5-M1

SDUI/codegen generates Document/Root and SDL/codegen generates Program, using
bounded deterministic Go literals, typed interface values and original source
positions. Constructors do not parse source. sdl-gen publishes both files and the
manifest atomically. Go symbols and setHandle/callback data survive; bridge.Plan
field mappings and domain functions remain handwritten Go.

CLI-generated `examples/generatedmodel` builds. Race tests compare every model field
against the frontend, independent constructor calls, byte-identical reproduction
and real runtime/bridge creation against separate simulation.Apt. Invalid profile,
root, package name and non-data Go values are rejected. `go test -race ./codegen`
passed in both modules, as did application tests.

## G5-M2

`sdl-simulate` starts from source; `sdl-compiled` uses generated constructors without
source files/parser calls. Both share application, runtime, bridge, handwritten
simulation and public draft/event paths. Tests build real executables and compare
complete JSON traces (errors, state, source links) for three event sequences.
Unregistered Go implementations fail at startup. Race tests passed.
`compiled-trace.json`: 430 → rejected invalid → 440, domain revision 2.

`sdl-compiled-fyne` builds with the desktop tag and uses the same generated models
and Fyne host. It adds no widget/layout implementation or source-file dependency.
The binary may contain the parser package as type owner; constructors do not parse.
Generated code does not translate undefined SDL domain behavior.

## G5-M3

`sdl-document` uses the same runtime property validation, Markdown provider,
measurement and SVG pipeline. Explicit value/label/enabled/visible are supported;
unknown widgets/types are rejected. No callbacks execute. Packages record input,
state, font/layout/generator/Go versions, source hashes and widget values. The Go
projector creates SDL navigation/overview. Race tests verify byte-identical repeats,
state selection, errors and actual projection without prerendering details.

`SDUI/design/runtime-preview` displays accepted 440 and the localized label `Bruk
verdi`. Its SVG was rasterized and visually checked (`runtime-preview.png`). The
compiled Fyne application started from an empty working directory with isolated
HOME/Xvfb and was checked (`compiled-native.png`). An initial probe found Xvfb had
exited; a fresh isolated server succeeded. No user display was used.

The full static export produced 170 diagrams / 539 files. All 538 output hashes
matched; all SVGs parsed. The use-case SVG was rasterized and checked. Publication
reads only previous ownership/hashes, so old renderer metadata does not block
migration; a regression test covers this. The original 170-diagram fixture remains
the port oracle. Current model status was updated separately after M4 verification.

## G5-M4

41 replaced source/test/oracle files were removed: active Python SDUI, design-core,
projectors, fixture builder and temporary Go control gallery. Console/Markdown and
general SVG now use current Go packages. Old prototype-svg/html flags are rejected.
93 SDUI and 151 SDL cases remain frozen; 170 projector fixtures retain their original
source. No active fallback. The [port inventory](../../docs/integration/SDL-Go-Port-Inventory.md)
separates other experiments.

Both race suites passed after deletion. Native broker/FOX tests used newly built Go
tools: lease, SIGKILL/restart, invalid source, replacement and native close passed.
The unused in-memory sequence table was removed; persistent Store alone owns ordering.

All 30 G-phase/milestone states in architecture.design became verified after actual
tests. AST/check, full export, navigator and UI/state package were regenerated by Go.
Inventories use Markdown headings with stable ID anchors, replacing raw HTML anchors
that XFMD displayed literally. Projector 1.1 invalidates caches. Dated Python evidence
is historical; current checkpoint, README, AGENTS, requirements and commands use Go.
Changed documents' local links were checked.

`tools/verify_release.py` is external test automation without language logic. It runs
both race suites with the real Mermaid backend, checks source hashes and generated
packages, and writes `release.json`.

Known independent deviation: the SDP validator fails on nine pre-existing
ITR/SLC/SPR IDs in Traceability/Relations.yaml. Toolkit/Traceability were unchanged
from sdp-vNow 9ad4324; see `sdp-validator-baseline.txt`. This is neither a passing
repository-wide contract check nor authorization to alter that other work.

Final release verification passed: 35 SDUI test/subtest results in 10 packages and
196 SDL results in 13 packages, zero failures. Port corpora also include cases inside
single test functions. Hash checks passed for 538 static, 14 navigation and 22 UI/state
outputs, excluding manifests; 170 full-export diagrams. `git diff --check` and changed
local links passed. New checkpoint addendum 11 preserves addendum 10's G6 design.
The original source-index capture remains, with a separate implementation update
and hash references.
