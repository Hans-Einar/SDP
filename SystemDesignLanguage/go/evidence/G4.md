# G4 — faktisk verifikasjon

## G4-M1

Go 1.27.1, strukturell design-core 0.5-port. `go test -race ./...` består.
151 fryste tilfeller fanget fra de eksisterende 61 Python-prøvene sammenligner
Go mot Python: hele AST-er med argument-/sluttposisjoner, diagnosekoder og spans,
og kanonisk tekst. Portverktøyet er kun et midlertidig fixture-orakel; Go åpner
ikke Python. Hovedmodellen for SDUI (463 deklarasjoner, 1424 fakta) gir identisk
full AST med den lagrede Python-eksporten og godkjennes kanonisk.

En femsekunders fuzz-kampanje med to workers fullførte 98 637 kjøringer uten
feil (verktøyets totalrunde ca. seks sekunder). Trunkering, UTF-8 og kildegrenser
har egne prøver. Grensene i Go er 2 MiB og 250 000 tokens; struktursykluser
kontrolleres iterativt. `sdl ast|check|format file|-` er kjørbar.

Dette beviser den eksisterende strukturelle profilen, data-/wirekontrakter og
Channel-/scenariovalidering. Det gjør ikke checkpoint-kandidater eller hele
MVP1-korpuset kjørbart. Runtime-handlingsprofilen følger G4-M2.

## G4-M2

Den eksplisitte `action-core 0.1`-profilen har egen grammatikk og kontrakt,
med felles SDL-lexer og posisjoner. `go test -race ./...` består; den fryste
strukturelle 0.5-porten er fortsatt identisk. `sdl action-check examples/echo.sdl`
rapporterer gyldig profil. Parserprøvene avviser ukjent versjon/type, manglende
signaturledd, gjentatte felter, udeklarert record og feil subjekt.

Runtime opprettes bare med komplett, typelik Go-registrering. Prøvene viser
streng input-/outputkontroll, kopierte recordverdier, uforanderlig kompilerings-
grunnlag, ubundet/mismatchet Go-signatur, stale modellrevisjon, duplikatkommando,
ugyldig output og handlerpanic uten automatisk gjenkjøring. Kallet er serialisert;
den registrerte funksjonen kan ikke re-entre samme Engine. Go-funksjonen eier
sitt domenestate. Dette er ingen automatisk utføring av design-core-fakta.

## G4-M3

`go test -race ./...` består. Echo-prøven kjører både knapp og input gjennom
SDUI-session → SDL action → registrert Go-funksjon → typet UI-oppdatering.
Negative bindingsprøver viser at feil modul, member, resultat-handle, feltkilde,
literaltype og ubrukt plan avvises uten delvis handlerinstallasjon eller domene-
kall. Linkene har kildeposisjoner på begge sider av språkgrensen.

EditAptCell-simuleringen sender celle `LengthA1`, draft og forventet domene-
revisjon. Godkjent 430 oppdaterer domene og UI; ugyldig verdi/stale revisjon
beholder forrige godkjente verdi og observerbar draft. Duplikatkommando kjøres
ikke igjen. `edit-apt-cell-trace.json` er produsert av `go run ./cmd/sdl-simulate`
for 430 → invalid → 440: domenerevisjon 2, akseptert verdi 440 og synlige utfall.

Den native OpenGL-proben `bridge/cmd/smoke` er bygget med desktop-tag og kjørt
under Xvfb. Native knapp sender 430 gjennom hele SDL/Go-grensen. Nytt ugyldig
edit avvises; Escape gjenoppretter 430 uten et nytt domenekall. To domeneinvokasjoner,
én godkjenning, én avvisning, domenerevisjon 1. `native-binding.png` er visuelt
kontrollert X11-opptak. Dette er simulering, ikke Ponsse-/maskinruntime.

Kjørbar vert: `go run -tags desktop ./cmd/sdl-demo` fra dette Go-området.
