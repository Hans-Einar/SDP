# Cross-repository evidence matrix

## Purpose and comparison rules

This matrix is the **OBSERVED** comparison layer for Issue
[#5](https://github.com/Hans-Einar/SDP/issues/5). It compares the 17 committed
repository reports; it is not the final synthesis and does not make a normative
workflow recommendation.

Evidence labels used in the matrix:

- **O-D — OBSERVED, DEFAULT:** evidence in the exact default-branch study tree
  recorded by `RepositoryInventory.md`.
- **O-ND — OBSERVED, NON-DEFAULT:** branch, open/draft PR, synthetic pull ref,
  or other unmerged evidence. It is never counted as default-tree adoption.
- **O-GH — OBSERVED, GITHUB:** live Issue, PR, review, check, or workflow state
  inspected by the repository report.
- **O-P — OBSERVED, PROPOSAL:** a committed or GitHub-visible proposal which
  was not exercised or accepted as the stated behavior.
- **I — INFERENCE:** a comparative classification derived from the observations.
  An inference is not owner direction or a recommendation.

`Strong`, `partial`, and `none` in the Issue-authority column use one consistent
rubric. **Strong** means an Issue or exact owner comment actually initiated or
bounded execution and carried material assignment authority such as scope,
baseline, branch/PR, verification, or stop conditions. **Partial** means an
Issue existed only after work started, remained an unexecuted later contract,
or otherwise did not authorize the studied execution. **None** means no GitHub
Issue was an authority for the studied work. The grade covers all evidence in
the row, while the `O-D`/`O-ND` labels show whether that evidence was accepted
default-tree practice.

Qualitative comparison words such as “strong,” “mixed,” “rich,” or “compact”
are **INFERENCE** judgements about the adjacent **OBSERVED** facts; they do not
state a recommendation.

## Limitations

- **OBSERVED:** repository reports inspect different process generations and
  different activity shapes. A default branch may be old while advertised
  non-default refs are active; the matrix preserves both facts instead of
  selecting the newest ref as canonical.
- **OBSERVED:** GitHub exposes most activity through the single identity
  `Hans-Einar`. Detailed repository records can show role-labelled passes and
  exact candidates, but they cannot independently prove fresh agent context or
  human/agent separation.
- **OBSERVED:** several reports rely on private repository links, local or
  hardware verification claims, and branch refs which require the same access
  or may later move. The exact commits and report evidence remain the study
  anchors.
- **OBSERVED:** no product or hardware verification was rerun for this matrix.
  It compares the evidence recorded by the 17 reports and their inspected
  GitHub state.
- **INFERENCE:** the Issue-authority grades and default-profile grouping are
  comparative abstractions defined above. The underlying row facts, exact
  merge/default boundary, and proposal/execution status remain more important
  than the grade.
