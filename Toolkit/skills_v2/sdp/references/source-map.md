# Resolve project authority

Use the actual project root and its applicable AGENTS instructions. Discover the
process entrypoint and declared local or installed profile before applying names
from another repository. SDP means System Design Process in this collection.

| Concern | Read when relevant |
| --- | --- |
| Current intent and accepted decisions | Mandate and affected Requirements, Architecture, Design; studies beside their phase |
| Selected work | Current card or Maintenance/Sprint/implementation plan; the project's actual work pointers |
| Shared management profile | SDP/ProjectManagement/README.md and SDP/KanBan/README.md when those roots are adopted |
| System implementation evidence | SDP/Traceability contract, related verification and actual source revision |
| Distributed Toolkit facts | Project manifest's installed pointer; installed Framework and version/capability facts |
| Skill availability | This skill's canonical source and siblings; actual host catalog and read evidence |

Do not treat a history directory, dated evaluation or backlog proposal as the
current authority. Older installed processes may require Slice/Fix/Iteration
records; preserve their supported contract until an authorized migration changes
it. Newer local processes may use optional Sprints and Maintenance directly.
Absence of a registry does not authorize inventing one. Follow the governing
profile and report a concrete compatibility gap instead of silently converting.

In the SDP Toolkit source repository, root Skills/ is the authored collection;
Toolkit/SDP-install.manifest.json defines installed copies. In consuming projects,
use the installed collection referenced by their AGENTS, not a guessed path back
to the producer. Archived draft evaluations remain historical evidence in the
producer's maintenance records and do not establish current activation.
