# G2 — verification evidence

Historical milestone observations; translation is not a new test run.

## G2-M1

Go 1.27.1 on Linux. Layout tests passed, measuring parsed sources including Concept1
without hand-positioned coordinates. Fr allocation covers minima, maxima and
saturation; scale overflow is rejected. Width-driven 16:9 derives height at two
viewports; a short viewport does not imply contain. Resize preserves font size.
Header/body/footer, circular size dependencies, clipping/hit tests and explicit
rejection of unimplemented scroll were tested. This proves measurement; SVG,
Fyne interaction and Markdown have separate milestones.

## G2-M2

Race tests passed. SVG tests cover XML, escaping, primitives and deterministic bytes.
CLI exported Concept1 with `--format svg --entry bucking --width 1920 --height 1200`
to concept1-layout.svg. rsvg-convert produced PNG; visual review confirmed six boxes,
1:1 and 25:50:25 columns, 15:45:40 rows, header buttons and bottom footer. Review
found missing vertical stretch, corrected in layout with a geometry regression test.
Text becomes outlines from the embedded measurement font; SVG titles preserve
literals for accessibility. No system font is required. Markdown was still raw text
in M2; its provider follows M4.

## G2-M3

Fyne 2.8.1 consumes layout.Box without reinterpreting SDUI rules. Native button/input
controls have clipping containers; shared SVG draws the background. Race tests
passed. Adapter tests cover callbacks, editing, focus order, disabled controls,
resize value preservation, teardown and clipped hit tests through Fyne canvas,
not only direct callback invocation.

The separate desktop-tagged acceptance probe ran with OpenGL under Xvfb :93,
FYNE_SCALE=1 and LIBGL_ALWAYS_SOFTWARE=1. A real window used Fyne test/focus APIs
for clicking/typing, resized 640×400 → 800×500 and verified one button callback
and input 312. No physical OS keyboard automation is claimed. native-window.png
was captured with ImageMagick import and reviewed. Canvas.Capture returned black
under this Mesa/Xvfb combination, so independent X11 capture supplied evidence.

One run took 1,250 ms start-to-completion including 750 ms planned waiting; one
synchronous resize/layout took 74,494 µs; Go heap was 48,128,456 bytes. A later run
had VmRSS 189,016 KiB. These are single observations, not benchmarks or a lightweight
guarantee. Startup exposed NaN from unbounded maximum × zero free space; it was
fixed. Ratio stretch and native minima also gained regression tests.

Build: `go build -tags desktop ./cmd/sdui-fyne`. Linux requires a C compiler and
Fyne OpenGL/X11 development libraries. Parser/layout/SVG have no native GUI imports.
Ordinary tests need no display; desktop is explicit for the native entry/probe.

## G2-M4

`SDUI_MMDR=/home/warloc/git/mermaid-rs-renderer/target/debug/mmdr go test -race ./...`
passed. Goldmark 1.8.2 parses Markdown structure. Tests cover headings, inline text,
lists, tables, diagram resources, missing providers, HTML/image rejection, source
limits, unverified diagram types and active SVG elements. The registered renderer
test checks actual Alpha/Beta labels and rectangular SVG nodes, plus separate,
idempotent resource export.

The CLI generated concept1-markdown.svg at 1920×1200, with resources in mermaid/.
Librsvg rasterization was checked: header buttons, formatted heading, table cells
and localized Rot→Kapp1→Kapp2→Topp inside the stem box. This proves flowcharts, not
all Mermaid types. The desktop Fyne CLI shares Markdown measurement but displays
a labeled diagram placeholder pending its own rasterization evidence.
