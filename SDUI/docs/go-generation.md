# Go generation — validated model constructors

The generator validates the whole source before writing Go. SDUI 0.2 and the
unreleased [0.3 development profile](profile-0.3.md) become a source-positioned
`Document()` and selected normalized `Root()`. SDL action-core 0.1 becomes a
`Program()` with records, actions and Go symbol references. These are typed Go
literals, not embedded source reparsed at startup. Each constructor call creates
independent models, preserving original positions, reuse paths and binding references.

`codegen.Generate(source, entry, pkg)` selects the generator identity from the
validated source profile. The AST format and generator identity describe different
contracts; neither is a claim of native or connected readiness.

| Source | Generator identity | Generated profile metadata |
| --- | --- | --- |
| `sdui 0.2;` | `codegen.Version`: `sdui-go-model/1` | No new constants; existing generated bytes preserved. |
| `sdui 0.3;` | `codegen.Version03`: `sdui-go-model/2` | `UIProfile = "sdui/0.3"`, `UIASTFormat = "sdui-ast/0.3"`. |

Both outputs include `UISourceSHA256`. In 0.2, `Instance.Profile` retains the empty
legacy sentinel and is omitted from generated literals; `Document().Profile`
still identifies `sdui/0.2`. In 0.3 every normalized instance carries `sdui/0.3`.
Use `parser.EffectiveProfile(root)` to validate and resolve a constructed root's
profile, and `parser.ASTFormat(profile)` for the corresponding AST envelope tag.
Do not relabel 0.3 as 0.2 or add empty profile fields to frozen 0.2 generated output.

Generated code contains model/binding data, not another runtime. For a collection
host, supply typed `runtime.CollectionProvider` bindings by normalized instance
path, with provider ID/epoch, initial data/root-loaded state and any application
loader. Reused collections need their own path bindings. Constructors contain no
live provider data, loader closures, selection or scroll state, and never load data.
An empty initial collection still needs an explicit provider; a source label or
callback reference is not a provider.

Use the same detached preparation as file-based startup: `preparation.Request`
receives the generated document, entry, providers, actual capabilities and layout
or state validation. Collection geometry requires the state-aware layout path;
the document-based Fyne host supplies that path and atomic publication. Connected
mode also requires a binder that validates loaded SDL modules, handwritten Go
functions and explicit `bridge.Plan` mappings before activation. Neither generation
nor static preview establishes connected readiness. Generation invents no domain
functions, storage, Channel transport or executable interpretation of design-core.
Wrong profiles and unknown roots reject before publication.

`sdl-gen -actions actions.sdl -ui page.sdui -entry page -package model -output DIR`
creates `actions_gen.go`, `ui_gen.go` and `manifest.json`. Bundle provenance uses
`sdl-go-model/1/sdui-go-model/1` for 0.2, or
`sdl-go-model/1/sdui-go-model/2` for 0.3, with source and output hashes. SDL's source
profile stays action-core 0.1. Existing 0.2 bundle bytes remain unchanged.
Publication preserves user-owned files and rejects modified generated files through
the existing manifest-managed atomic publisher. Build against matching Go modules;
language-model hot reload and Go rebuild/restart remain distinct mechanisms.
