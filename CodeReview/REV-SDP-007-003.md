### High

#### H-001 — Assignment acceptance and conflict state can contradict the validated graph

**Locations:** `SDP-vnext-pilot/WorkflowContract.md`, especially lines
132-151 and 225-293; `SDP-vnext-pilot/ConcurrentAssignments.md`, lines
95-126; and `SDP-vnext-pilot/validate_pilot.py`, lines 891-992,
1083-1207, 1253-1447, and 1450-1654.

The contract separates declared from accepted state and says each accepted
Slice/standalone Fix has qualifying evidence. It also says a dependent
candidate cannot receive accepted state until its prerequisite gate is
satisfied, and a `conflictsWithIssues` edge blocks concurrent activation. The
validator checks each accepted-evidence object syntactically and checks the
reservation DAG structurally, but never relates those two checks.

Fresh, digest-correct mutations returned no diagnostics for all of these:

- the simple assignment declared `accepted` with a qualified exact-candidate
  evidence object while its only `SLC-001` remained `active` with null accepted
  evidence;
- scoped Issue 203 declared `accepted` while its own Slice remained `proposed`
  and its dependency Issues 201 and 202 remained `active`; and
- Issues 201 and 202 declared symmetric conflict edges while both assignment
  records remained `active` in the same current reservation set.

Feature/Refactor lifetime state need not become delivered after every accepted
assignment, but the assignment's bounded Slices/Study and prerequisite gates
must support its acceptance. A symmetric conflict is explicitly a blocked
declaration, not permission for two active Masters. The present PASS can
therefore attest the opposite of the contract's concurrency and accepted-state
rules.

**Required remediation:** define and validate the cross-record state rules.
At minimum, an accepted implementation assignment must be supported by its
bounded Slice acceptance/convergence evidence; an accepted Study assignment
must be supported by the primary Study; a current dependent cannot be accepted
while an in-set prerequisite is unsatisfied; and conflict endpoints cannot be
concurrently active. Preserve the valid case where a durable Feature remains
active across several accepted assignments. Add exact fixtures for assignment/
Slice candidate-state mismatch, unsatisfied dependency acceptance, and active
symmetric conflicts.

#### H-002 — Embedded work/Study/Fix edges evade the qualified relation contract

**Locations:** `SDP-vnext-pilot/WorkDomains.md`, lines 27-39 and 87-101;
`SDP-vnext-pilot/WorkflowContract.md`, lines 33-93 and 132-151; the Feature,
Refactor, Fix and Study templates; and `SDP-vnext-pilot/validate_pilot.py`,
lines 85-110, 718-808, and 1210-1232.

Pilot templates require Feature/Refactor `relations`, Fix `affectedWork`, and
Study `ownerRef`/`independentStudyRefs`/`informs`. WorkDomains says a relation
to another domain MUST use `{domainUid,id}`. The validator validates only the
top-level `relations` array and Slice references. For the embedded fields it
checks only that a list exists; a Study owner needs only a two-string object
and is not resolved.

Fresh mutations returned no diagnostics when:

- `DBG-FEAT-001.relations` contained bare cross-domain `HSX-STU-001`;
- `AVR-STU-001.ownerRef` named nonexistent `AVR-FEAT-999`;
- that Study's `informs` contained bare `DBG-FEAT-001`; and
- an otherwise valid delivered, low-risk, standalone zero-Slice Fix named an
  unresolved qualified `FEAT-999` under `affectedWork`.

The last case is material to the proportional exception: without a valid edge
to accepted behavior, the record does not establish that it is a correction
rather than unanchored capability work. More broadly, accepting bare embedded
references defeats scoped identity even though the equivalent top-level edge
would be rejected.

**Required remediation:** choose one pilot representation for these semantic
edges. Either define and validate their qualified shapes, target kinds,
cardinalities and local resolution, or remove them from typed records and use
the validated top-level relation graph exclusively. A standalone delivered
Fix must bind its correction to the affected accepted work/release evidence.
Add exact cross-domain/bare/unresolved/wrong-kind fixtures for each retained
edge surface.

### Medium

#### M-001 — Reusable revision history can be absent, invented, or truncated

**Locations:** `SDP-vnext-pilot/ConcurrentAssignments.md`, lines 35-74;
`SDP-vnext-pilot/IssueContract.md`, lines 98-102; and
`SDP-vnext-pilot/validate_pilot.py`, lines 1657-1725 and 2060-2130.

The final dogfood revision-1-to-2 snapshot is correctly bound to the real
historical Git object. The reusable validation is weaker and the Git check is
hard-coded to Issue #7.

Fresh mutations showed:

- changing the simple assignment from revision 1 to revision 2 while omitting
  `previousRevision`, `refreeze`, and all history returns `[]`;
- a syntactically complete revision-2 history citing a nonexistent
  `aaaaaaaa...` source candidate and invented prior digest returns `[]`;
- revision 3 with only an invented revision-2 snapshot returns `[]`; but
- retaining both revision-1 and revision-2 snapshots for revision 3 returns
  `INVALID_ASSIGNMENT_REVISION_HISTORY`, because every history source not
  referenced directly by the current assignment is rejected and snapshots
  have no previous link.

Thus a downstream pilot can lose or invent the exact reservation refreeze the
history is meant to preserve, while a complete multi-refreeze chain is not
representable in the validated aggregate.

**Required remediation:** require revision 1 to have no predecessor and every
revision greater than 1 to have an immediate predecessor/refreeze. Give
snapshots a validated previous link or another complete chronological chain
representation, reject gaps, retain all earlier snapshots, and verify exact
source-candidate assignment/reservation bytes whenever the source is local.
Make the repository-aware check generic rather than tied to ISSUE-007 paths.

#### M-002 — Portable path and shared/boundary values remain under-validated

**Locations:** `SDP-vnext-pilot/WorkDomains.md`, lines 191-225;
`SDP-vnext-pilot/ConcurrentAssignments.md`, lines 95-108;
`SDP-vnext-pilot/validate_pilot.py`, lines 263-312, 831-888, and
1600-1618.

WorkDomains explicitly rejects control characters and platform-reserved path
semantics. Fresh owned-path mutations containing each of `|`, `"`, `<`, C1
control U+0085, and bidi format control U+202E all returned `[]` after the
reservation digest was rebound. Windows forbids `"<>|`; Unicode Cc/Cf controls
also make portable comparison and review unsafe.

Two adjacent value failures also return `[]`:

- `boundaries.prohibitedPaths: ["../escape"]`, which cannot express a valid
  repository-relative safety boundary; and
- a shared touchpoint whose `allowedMutation` is whitespace only.

The validator currently checks these boundary fields only as nonblank string
lists and tests shared mutation by ordinary string truthiness.

**Required remediation:** apply one NFKC-first portable path validator to every
path-bearing contract field, reject the complete conservative Windows-forbidden
set and Unicode control/format categories, and require a nonblank shared
mutation description. Add exact fixtures for the demonstrated characters and
invalid prohibited/shared values.

#### M-003 — Prospective source paths are not unique

**Locations:** `SDP-vnext-pilot/WorkflowContract.md`, lines 169-190;
`SDP-vnext-pilot/WorkDomains.md`, lines 102-130; and
`SDP-vnext-pilot/validate_pilot.py`, lines 386-445 and 1022-1080.

The candidate correctly binds each prospective record's declared `source` to
its own inventory member. It does not prevent two different identities from
claiming the same source.

In a fresh mutation, both `FEAT-001` and `SLC-001`, and both corresponding
inventory members, were assigned exact source `Features/FEAT-001.json`.
Validation returned `[]`. A single-record JSON path cannot resolve exactly to
both represented records, so this defeats the claimed source binding and
creates a portable case/slash collision risk on real filesystems.

**Required remediation:** enforce normalized portable source-path uniqueness
for prospective inventory/record bindings within a repository, unless a future
explicit multi-record container schema defines stable member addressing.
Resolve local sources generically when present and add exact, case, slash and
Unicode-equivalent duplicate-source fixtures.

### Low

#### L-001 — Move/navigation hints can be unusable or misleading

`WorkDomains.md` makes UID/ID authoritative, so this does not rewrite identity.
However, replacing the move tombstone's `successorRegistry` with
`not-a-location` returns `[]`, and replacing an HSX target `keyHint` with `AVR`
also returns `[]`. Validate a successor registry as an explicitly supported
canonical URL or portable path, and diagnose a supplied key hint that
contradicts the resolved UID's key.

#### L-002 — Unsupported schema markers are treated as pilot v0

Replacing a Feature's schema marker with `unknown-future-schema` returns `[]`.
Even while serialization remains provisional, the v0 validator should reject
unknown markers or report them as unsupported rather than silently applying v0
semantics.
