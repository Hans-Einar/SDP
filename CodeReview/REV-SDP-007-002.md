### High

#### H-001 — GitHub Issue identity aliases bypass one-Issue/one-assignment safety

**Locations:** `SDP-vnext-pilot/WorkflowContract.md`, lines 107-113 and
132-151; `SDP-vnext-pilot/ConcurrentAssignments.md`, lines 18-29 and 95-105;
`SDP-vnext-pilot/validate_pilot.py`, lines 451-473, 800-814, 917-961; and
`SDP-vnext-pilot/templates/issue-assignment.template.json`, lines 7-14.

The contract uses a GitHub Issue as the globally addressable assignment
identity and requires every current reservation node to have a unique Issue
authority. The validator does not define or parse that identity. It uses the
raw string in `authority.issue`, `authorityIssue`, reservation rows,
dependencies, conflicts, and merge order.

A fresh mutation changed Issue 202 into a second spelling of Issue 201 by using
`.../issues/201/` while Issue 201 retained `.../issues/201`, updated every
corresponding record/reservation edge, and rebound the digest. Validation
returned `[]`. GitHub's API independently resolves a zero-padded request such
as `Hans-Einar/SDP/issues/007` to canonical Issue 7, demonstrating that textual
URL aliases are not hypothetical Issue identities.

The same gap accepts `not-a-github-issue` as the authority when all projections
copy it. A pilot can therefore start two Masters for one real Issue, evade the
duplicate-node rule, and produce a reservation/DAG that looks distinct only by
URL spelling.

**Required remediation:** define the pilot's canonical GitHub repository,
Issue, Issue-comment amendment, and PR reference shapes. Parse and compare an
Issue by canonical host/owner/repository/numeric Issue identity, reject query,
fragment, slash, leading-zero, case, or transport aliases where they are not
the canonical authored form, and require repository coherence for Issue/PR
bindings. Apply that identity to assignments, owner/Study authorities,
inventory members, reservation rows, dependency/conflict edges, and merge
order. Add exact alias/non-URL/repository-mismatch fixtures.

#### H-002 — Registry-set partitioning bypasses key and root collision checks

**Locations:** `SDP-vnext-pilot/WorkDomains.md`, lines 17-56, 66-83, and
121-153; `SDP-vnext-pilot/OpenQuestions.md`, question 3; and
`SDP-vnext-pilot/validate_pilot.py`, lines 283-369.

WorkDomains requires keys to be unique among active/tombstoned domains in one
repository and active roots to be non-overlapping. `validate_registry_set`
creates `per_repo_keys` and `root_entries` inside each registry loop. It never
groups registry objects by canonical repository identity.

A fresh mutation duplicated the simple example's registry, retained the same
repository URL, key `TINY`, and root `SDP`, changed only the second domain UID,
and removed its issued IDs. Validation returned `[]`. The candidate therefore
accepts two active owners for the same portable root under the same repository
and lets both domains mint the same visible prefix. This also leaves the open
one-versus-several-registry placement choice unsafe: either duplicate registry
records must be rejected, or collisions must be checked across all registry
parts for one repository.

**Required remediation:** define canonical repository identity, reject
duplicate registry declarations unless an explicit multi-part registry model
is selected, and in either case aggregate all active/tombstoned declarations
for per-repository key/default-domain/root collision checks. Add duplicate-
repository, cross-registry key, cross-registry exact-root, and cross-registry
parent-root fixtures.
